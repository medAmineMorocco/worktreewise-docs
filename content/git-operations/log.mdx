# Git Log & Working Tree

The **Git Log** is the central commit visualizer and working tree manager in WorktreeWise. It combines a high-performance interactive commit graph with real-time working tree status, inline file staging, commit authoring, and diff inspection.

To open Git Log:
- Select **Git Log** in the sidebar.
- Or press the global shortcut **Shift + G**.

![Git Log](/images/releases/1.1.0/01-git-log.png)

---

## Toolbar Controls & Filtering

The Git Log toolbar provides immediate access to repository filters and operations:

### 1. Worktree & Scope Selection

Select any active worktree from the dropdown to scope the commit graph and working tree view to that specific branch. Switching worktrees updates the commit graph and working directory status immediately.

### 2. Author Search & Filtering

Filter commits by contributor using the searchable **Author** dropdown. Search by name or clear the filter to restore all contributors.

### 3. Column Visibility & Privacy Controls

Select **Columns** to customize which columns are displayed in the commit table:
- **Author**: Shows or hides contributor names and avatar indicators.
- **Date**: Shows or hides relative and absolute timestamps.
- **SHA**: Shows or hides Git commit hashes.
- **Refs**: Shows or hides branch and tag reference badges.

![Git Log column controls with Author disabled](/images/releases/1.1.0/02-git-log-columns.png)

<Callout type="tip">
Disabling the **Author** column is useful during screencasts, product demos, or public tutorials to protect contributor privacy while keeping commit messages and graphs visible.
</Callout>

### 4. Git Quick Actions

Trigger standard Git operations directly from the toolbar:
- **Pull**: Fetches and merges remote changes into the currently selected worktree.
- **Push**: Pushes local commits to the tracked upstream branch.
- **Stash**: Stores uncommitted local modifications in Git stash storage.
- **Pop**: Restores the most recently stashed changes into your working tree.
- **Diff (`Shift + D`)**: Opens the pairwise [Git Diff](/git-operations/diff) comparison modal.
- **Reload (`⟳`)**: Re-reads commit history and working tree status from disk.

## Working Tree & Inline Staging

At the top of the commit graph, the **Working Tree** row displays the live status of uncommitted modifications in the active worktree:

- **Change Badges**: Displays color-coded counts of modified (blue), added (green), and deleted (red) files.
- **Automatic Sync**: The working tree polls for file modifications every 4 seconds and automatically refreshes whenever the application window regains focus.

### Staging and Discarding Changes

Selecting the **Working Tree** row opens the staging panel on the right:

1. **Staged vs. Changes**: Files are organized into **Staged Changes** and **Changes** (unstaged).
2. **Stage / Unstage All**: Move all files between staged and unstaged states with a single click.
3. **Per-File Controls**: Select `+` beside a file to stage it, or `-` to unstage.
4. **Discard Changes**: Select the trash icon on an unstaged file to revert modifications:
   - Modified files revert to their `HEAD` state.
   - Untracked files are deleted after explicit confirmation.

## Commit Details & File Diffs

### Inspect Working Tree Changes

Selecting any file in the Working Tree panel opens the **File Diff Pane**:
- Highlights additions (green) and deletions (red) with code syntax highlighting.
- Displays line addition and deletion counts.
- Provides **Stage**, **Unstage**, and **Discard** actions directly in the diff header.

### Inspect Historical Commits

Selecting any commit in the commit graph opens the **Commit Details Panel**:
- Displays the full commit SHA, author, timestamp, parent commits, and commit message.
- Summarizes total changed files and aggregate line metrics (`+additions` / `-deletions`).
- Lists all modified, added, or deleted files. Selecting any file renders its exact commit diff.

## Performance & Virtualization

- **Gzip Stream Compression**: Git Log output is compressed with gzip and decompressed on the client using `pako.ungzip`, ensuring fast transfer times across repositories with tens of thousands of commits.
- **Virtualized Infinite Scroll**: Commits render in paginated increments of 40 (`LIMIT = 40`), maintaining smooth 60fps scrolling and low memory usage.
